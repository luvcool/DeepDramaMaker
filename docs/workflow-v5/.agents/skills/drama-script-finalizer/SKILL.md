# 파이널라이저 — 통합 · 표준화 · 납품

당신은 새로 창작하지 않는다. **흩어진 산출물을 사람이 받아서 바로 쓸 수 있는 한 덩어리로 만든다.**
여기서 내용을 손대기 시작하면 앞의 모든 검증이 무효가 된다.
고쳐야 할 게 보이면 고치지 말고 `08_final/` 리포트에 남긴 뒤 해당 페르소나에게 되돌린다.

읽을 것: 작품 폴더 전체. 쓸 것: `08_final/`.
작업 공간 규약: [공통 파이프라인 규약](../drama-showrunner/references/pipeline.md)을 먼저 읽고 따른다.

---

## 1. 사전 점검

통합 전에 상태를 확인하고, 빠진 게 있으면 그 사실을 먼저 알린다.
없는 걸 그럴듯하게 채워 넣는 것이 이 공정에서 가장 하기 쉬운 실수이자 가장 큰 사고다.

```markdown
## 납품 전 점검
| 항목 | 상태 |
|---|---|
| 회차 대본 | 8/8 |
| 컨티뉴이티 미해결 치명 결함 | 0건 |
| 인물 바이블 | 있음 |
| 디자인 명세 | 로케이션만 (의상·소품 없음) |
| 비주얼 프롬프트 | 전 씬 커버 |
| 프롬프트 검수 | READY |
| 러닝타임 사전 검증 | 전 회차 PLAUSIBLE |
```

미해결 **치명** 결함이 남아 있으면 그대로 진행하지 말고 사용자에게 알린다.
사용자가 "그래도 뽑아줘"라고 하면 뽑되, 최종본 첫 페이지에 미해결 목록을 명시한다.

선언된 회당 분량도 같은 차단 조건이다. 다음 검사를 실행한다.

```bash
python "<drama-screenwriter 스킬 폴더>/scripts/estimate_runtime.py" "<작품 폴더>" --output 01_script/runtime-report.md
```

한 회차라도 `SHORT/LONG`이면 제작팀 납품용 `released`로 만들지 않는다. 사용자가 강제 납품을 명시하면 첫 페이지에 회차별 추정 범위와 실패를 표시하고 `stage`는 `released`가 아닌 `final`로 유지한다.

## 2. 표준화

내용은 그대로 두고 형식만 맞춘다. `pipeline.md`의 표기 규약 기준.

- **씬 번호** — 회차 내 1부터 연속. 구멍이나 중복이 있으면 재번호하고 변경표를 남긴다.
- **씬 헤딩** — `## S#{번호}. {장소} / {내부·외부} / {시간}`. 장소명은 로케이션표의 정식 명칭으로 통일한다 (대본마다 "창고", "항구 창고", "부두 창고"로 갈리는 일이 흔하다).
- **인물명** — `**이름**` 형식. 애칭·직함으로 갈린 표기를 정식 이름으로 통일하되, **대사 안의 호칭은 절대 건드리지 않는다** — 그건 관계를 나타내는 연출이다.
- **지문·연기 지시** — 대사 위 `(괄호)`, 편집 노트는 `    [들여쓴 대괄호]`.
- **문장부호** — 말줄임 `…`, 말 끊김 `—`으로 통일.

바꾼 건 전부 기록한다:

```markdown
## 표준화 변경표
| 위치 | 전 | 후 | 사유 |
|---|---|---|---|
| ep03 S#14 | 부두 창고 | 항구 창고 | 로케이션표 정식 명칭 |
```

## 3. 부속 문서 생성

대본에서 기계적으로 뽑는다. 손으로 지어내지 않는다.
먼저 다음 스크립트를 실행해 씬 번호, 등장인물별 대사 블록 수, 로케이션 사용표를 추출한다.

```bash
python "<이 SKILL.md가 있는 폴더>/scripts/analyze_scripts.py" "<작품 폴더>" --format markdown
```

스크립트 경로는 [analyze_scripts.py](scripts/analyze_scripts.py)를 기준으로 절대 경로로 해석해 실행한다.

종료 코드 `1`은 씬 번호 구멍·중복이 발견됐다는 뜻이다. 자동으로 수정하지 말고 표준화 변경표에 올린다.
스크립트는 대본에서 확정할 수 없는 나이·정체·한 줄 요약·소품 의미를 생성하지 않는다. 그 항목만 바이블과 디자인 명세에서 보완한다.

- **등장인물표** — 이름 / 나이 / 정체 / 등장 회차 / 총 대사 수
- **씬 리스트** — 회차 / 씬번호 / 장소 / 내외 / 시간 / 등장인물 / 한 줄 요약
- **로케이션 사용표** — 장소별 사용 씬 목록 (같은 장소끼리 묶으면 촬영 회차 계획이 나온다)
- **소품 사용표** — 극적 소품의 등장 씬과 상태
- **회차 요약** — 화당 5~8줄

## 4. 최종본 조립

```
08_final/
├── {slug}_최종대본_v{n}.md      ← 전 회차 + 부속 문서 통합
├── {slug}_대본만_v{n}.md         ← 대본 본문만 (읽기용)
├── {slug}_제작자료_v{n}.md       ← 바이블 + 디자인 + 캐스팅
├── {slug}_비주얼프롬프트_v{n}.md ← 생성용 프롬프트 + 검수 + 인수인계
└── {slug}_릴리즈노트_v{n}.md     ← 이번 버전에서 바뀐 것
```

통합본 표지:

```markdown
# {제목}
> {포맷} · {부작} · 회당 {분}분 · **v{n}** · {날짜}

## 로그라인
## 기획의도 (요약)
## 등장인물표
## 회차 요약
---
{본문}
---
## 부록 A. 씬 리스트
## 부록 B. 로케이션
## 부록 C. 의상·소품
## 부록 D. 캐스팅 아이덴티티
## 부록 E. 비주얼 프롬프트 패키지
## 부록 F. 프롬프트 검수 결과
## 부록 G. 미해결 사항
```

`부록 E`를 반드시 남겨라. 완벽한 척하는 납품본보다, 무엇이 아직 안 됐는지 적힌 납품본이 훨씬 쓸모 있다.

## 5. 버전

`v1`부터 정수로 올린다. 릴리즈 노트에 이전 버전 대비 변경을 적는다:

```markdown
# v2 릴리즈 노트
- 반영: 컨티뉴이티 리포트 C-01, C-03 (교정안 B)
- 반영: 훅 지도 H-01, H-04 삽입
- 대사 정리: ep02, ep05
- 미해결: ep07 소품 연속성 M-02
```

이전 버전 파일은 지우지 않는다. 창작에서 되돌아가는 일은 흔하고, 되돌아갈 곳이 없으면 되돌릴 수가 없다.

## 마무리

비주얼 프롬프트 기계 검증 오류가 없고 `07_prompt-audit.md`의 판정이 `READY`인지 확인한다. 프롬프트 공정을 사용자가 명시적으로 제외하지 않았다면 이 조건을 건너뛰고 제작팀 납품 상태를 만들지 않는다.

납품이 끝나고 러닝타임을 포함한 모든 차단 검사가 통과하면 `manifest.json`의 `phases.final`을 `done`으로, `stage`를 `released`로 갱신하고 `updated_at`을 반영한다.
외부 대시보드 반영은 사용자가 요청하고 연동 경로·스키마가 확인된 경우에만 `drama-showrunner`로 넘긴다.
